The Analytics dashboard gives you a historical view of token consumption and estimated cost across all your agents — so you can see trends, identify top spenders, and plan capacity.

## Accessing analytics

Go to **Dashboard → Analytics** in the sidebar.

---

## Token snapshot analytics

The top section tracks token consumption using periodic snapshots from OpenFang metrics.

### Taking a snapshot

Click **Snapshot now** on the Analytics page to record the current token state.

For automatic tracking, trigger snapshots from a cron job or CI pipeline:

```bash
curl -X POST https://your-clawhq-domain/api/analytics
```

Each snapshot is stored in `/data/analytics.json` (Docker) or `.analytics.dev.json` (dev). Up to 720 snapshots are retained (30 days at hourly cadence).

### Time ranges

Use the **24h / 7d / 30d** selector to filter the time window. All KPIs and charts update to reflect the selected range.

### What's shown

| Metric | Description |
|--------|-------------|
| Tokens used | Total tokens consumed across all agents in the window |
| Estimated cost | Blended cost estimate at $0.30/1M tokens |
| Daily average | Average daily token consumption |

The per-agent breakdown shows each agent's contribution as a bar chart and sortable table with tokens and estimated cost.

## Agent cost trend

The **Agent Cost Trend** panel appears below the snapshot section and pulls directly from the `cost_events` database table — giving you precise, per-call cost data rather than estimates.

This data is recorded automatically every time an agent runs. No manual snapshots required.

### Time ranges

Use the **30d / 60d / 90d** selector to adjust the lookback window.

### What's shown

| Metric | Description |
|--------|-------------|
| Total spend | Actual cost in dollars (from recorded API fees) for the window |
| Total tokens | Input + output tokens across all agent runs |
| Total runs | Number of agent executions in the window |
| Top agent | Agent with the highest spend, and their total cost |

**Daily spend chart** — stacked area chart showing each agent's daily cost contribution. Useful for spotting growth in a specific agent's usage or unexpected cost spikes.

**Spend by agent** — horizontal bar chart ranking agents by total spend for the period, with a detail table showing tokens, run count, cost-per-run, and total cost per agent.

### API endpoint

The underlying data is available directly:

```bash
# Daily cost trend (default 30 days, max 90)
GET /api/companies/:companyId/costs/trend?days=30

# Total cost by agent for a date range
GET /api/companies/:companyId/costs/by-agent?from=2026-01-01&to=2026-01-31
```

The dashboard proxy also exposes these at `/api/costs?endpoint=trend&days=30` without requiring a companyId.

### Cost-per-run interpretation

The detail table shows **cost/run** — total spend divided by number of executions for each agent. Use this to identify:

- Agents running expensive models on simple tasks (high cost/run, low token output)
- Agents with growing run frequency driving up total spend
- Agents where prompt caching should be enabled (see [Budget & Cost Controls](/guides/budget))

---

## Customizing cost rates

The snapshot section uses a blended estimate of $0.30/1M tokens. The Agent Cost Trend panel uses actual recorded costs from API billing events — no adjustment needed.

For provider-level caps and budget enforcement, see [Budget & Cost Controls](/guides/budget).

## Data storage

- **Snapshot analytics**: stored as JSON (`/data/analytics.json`). Back up to S3/R2 for retention beyond 30 days.
- **Agent cost trend**: stored in the Paperclip PostgreSQL database (`cost_events` table). Retained indefinitely — no automatic pruning.
