Running 30 AI agents
on a $5/mo VPS

ClawHQ's full Docker Compose stack runs on a 1 vCPU / 1 GB RAM instance. The secret: the VPS only runs the orchestration layer — all LLM inference goes through your own API keys.

May 6, 2026 · 7 min read

When people hear "30 AI agents," they assume you need a beefy server, a GPU, or a managed platform charging $300/month. None of those are true for ClawHQ.

ClawHQ separates the orchestration layer (routing, memory, security, channels) from the inference layer (the LLM calls that actually generate text). The orchestration layer is lightweight — it's routing logic, SQLite, and a Next.js dashboard. The inference layer runs at Anthropic, OpenAI, or wherever your API key points. Your VPS never touches a GPU.

The actual resource footprint

Here's what ClawHQ's five services use at idle on a standard Linux VPS:

Service Role RAM (idle) RAM (peak) CPU (idle)
openclaw API gateway + LLM router 60 MB 120 MB <1%
openfang Agent OS (Rust binary) 28 MB 80 MB <1%
paperclip Orchestration + pack registry 90 MB 180 MB <1%
hermes Conversational AI (chat) 55 MB 140 MB <1%
dashboard Next.js UI (SSR) 110 MB 220 MB <2%
Total ~343 MB ~740 MB <5%

A 1 GB RAM instance (Hetzner CX11: €3.79/mo, DigitalOcean Droplet: $4/mo, Linode Nanode: $5/mo) runs the full stack with 250+ MB headroom. The OS and Docker daemon add another ~200 MB, which still leaves room.

A 2 GB instance ($8–10/mo) is more comfortable if you're running 10+ agents concurrently or have multiple channels active. It's not required — but it gives you breathing room under load.

Why BYOK changes everything

Most "AI agent platforms" bundle LLM inference with their platform cost. You pay $100/month and get X credits — and you're on their infrastructure, their rate limits, their model selection.

ClawHQ is BYOK: bring your own keys. Your Anthropic key, your OpenAI key, your OpenRouter account. The inference calls go directly from ClawHQ to the provider. The VPS is just the traffic cop — it routes the request, applies security rules, logs the cost, and passes the response back to the right channel.

The math for a small team:

  • VPS cost: $5–10/month
  • ClawHQ: free (MIT license, self-hosted)
  • LLM costs: whatever you actually use — Anthropic Claude Sonnet 4.6 runs ~$3/MTok input, ~$15/MTok output. At moderate usage (1M tokens/month), that's $3–15/month
  • Total for a team of 3: ~$20–30/month

Compare that to a SaaS agent platform charging $50–100/seat/month with bundled — and metered — AI credits. The self-hosted math wins at almost any usage level.

What "30 agents" actually means

An agent in ClawHQ is a configured process definition — a name, a model, a system prompt, channel assignments, and tool access. At idle, an agent is just a row in SQLite. It consumes no RAM, no CPU.

Agents only use resources when they're actively processing a request. Concurrent agent load is what matters, not the total agent count. On a 1 GB VPS, you can comfortably handle 5–8 concurrent agent invocations before you'd notice latency.

For most small teams (3–10 people), concurrent load never exceeds 3–4 agents at once. 30 configured agents running serially is no different than 3.

The one exception: local model inference

If you want to run Ollama locally alongside ClawHQ — pulling a 7B or 13B model onto the same machine — then yes, you need real hardware. A 7B model at 4-bit quantization needs ~4 GB RAM just for the weights, plus overhead. You're looking at a machine with 16+ GB RAM and a decent CPU (or a GPU node).

But that's a deliberate choice, not a requirement. Most ClawHQ deployments route to hosted APIs. Local inference is an option for air-gapped environments, ITAR compliance, or edge cases where latency to a remote API is unacceptable.

ClawHQ + Ollama setup

Set OPENCLAW_LOCAL_MODEL=ollama/llama3.2 and OLLAMA_BASE_URL=http://localhost:11434 in your .env to route specific agent tasks to a local model. All other agents continue using your cloud API keys. You can mix local and remote per-agent.

Deploying to a VPS

The full setup from a fresh Ubuntu 24.04 VPS:

# Install Docker
curl -fsSL https://get.docker.com | sh
usermod -aG docker $USER && newgrp docker

# Clone and deploy ClawHQ
curl -fsSL https://install.clawhqplatform.com | bash

The install script pulls pre-built Docker images from GitHub Container Registry and starts all five services. No Rust compilation, no Node.js setup, no Python environment. The dashboard is available at http://your-ip:3500 within 2–3 minutes of the first pull completing.

For production, you'll want nginx in front for TLS:

server {
    listen 443 ssl;
    server_name yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:3500;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

Let's Encrypt handles the certificate. The entire setup — VPS + DNS + nginx + ClawHQ — takes under 30 minutes.

VPS recommendations by use case

  • Solo / personal: 1 GB RAM, 1 vCPU — Hetzner CX11 at €3.79/mo is the minimum viable server
  • Small team (2–5 people): 2 GB RAM, 2 vCPU — $8–12/mo from any major provider
  • Team (5–20 people) with active channels: 4 GB RAM, 2–4 vCPU — $20–40/mo
  • Enterprise / high-concurrency: 8+ GB RAM — consider Kubernetes or Docker Swarm across multiple nodes

At every tier, the AI inference cost scales with usage, not server size. Your VPS cost is nearly flat as your team grows — it's the API usage that scales linearly.

The point of ClawHQ isn't to be cheap. It's to give you control. You know exactly what you're spending, you own the data, and you can move the whole stack to different hardware in 10 minutes with a single command.

The $5/mo VPS story is the proof that the architecture is right — not that you should try to run everything on the smallest possible machine.
